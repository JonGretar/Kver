# Domain docs

Kver uses a single-context layout: `GLOSSARY.md` at the repository root and ADRs under `docs/adr/`.

Before exploring a relevant area, read the glossary and any applicable ADRs. If they do not exist yet, proceed without creating empty files. Add a glossary entry when a domain term is settled; record a consequential architectural decision when its trade-offs need preserving.

Use glossary terms consistently in issues, design discussions, hypotheses, and tests. Flag a proposed change that conflicts with an existing ADR rather than silently overriding it.
